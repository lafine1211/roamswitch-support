# Zero Telemetry 監査 — 結果（2026-08-29）

[English](RESULTS-2026-08-29.md) | **日本語**

- **判定：PASS**
- ツール：[`rs-zerotel-audit.sh`](rs-zerotel-audit.sh)（このフォルダ）
- 環境：macOS 26 / Apple Silicon
- RoamSwitch：1.4.7
- ウィンドウ：約2時間の1セッション

## 実施方法

開発者の日常マシンで実施しました。Claude Code・IDE・通常の iCloud サービスが
稼働しており、**「沈黙したマシン」という主張ではありません**。手法はプロセス帰属です：
`tcpdump`（全インターフェース）、`nettop` のカウンタと `lsof` の定点観測による
ソケット→プロセスの対応づけ、RoamSwitch のバイナリに絞った Apple `pktap` キャプチャ、
LuLu の統一ログイベント。RoamSwitch のセキュリティレベルはウィンドウ全体で
**最大ロックダウン**に手動オーバーライドで固定（`pf` ルールが最大でも、宣言した
4経路だけを通すこと）。セッション中に appcast チェックを強制（`SULastCheckTime`
消去＋再起動）、MCP の全ツールを stdio で実行、`freshclam` を実行、アプリ内の
全機能を1回ずつ行使、ネットワーク遷移を1回。

許可リスト（これ以外が RoamSwitch のプロセスから出たら不合格）—
[`docs/WHITEPAPER.ja.md`](../docs/WHITEPAPER.ja.md) §7 より：

| # | 宛先 | プロセス | 発生条件 |
|---|---|---|---|
| 1 | `lafine.net /api/v1/license/*` | RoamSwitch | ライセンス認証／解除のときだけ |
| 2 | `lafine.net /updates/appcast.xml` | RoamSwitch | Sparkle（起動時＋24時間ごと） |
| 3 | ClamAV のミラー | `freshclam`（アプリ本体ではない） | ClamAV 導入時のみ |
| 4 | 対象 URL への `HEAD` | RoamSwitch | アプリ内「リンク安全性診断」を使ったときだけ |

## 結果

**`RoamSwitch` / `RoamSwitchHelper` / `RoamSwitchMCPServer` に帰属する
非ローカルの外向きフロー：なし。** この3プロセス名に絞った `pktap` の
キャプチャパケットはゼロ。

**MCP サーバー：** 開いたソケットは `127.0.0.1`（ローカルホスト）のみ —
`get_exposed_ports` ツールがローカルの待受ポートの HTTP ヘッダを見に行ったもの。
読み取り専用・stdio でのみ通信し、外には何も出ていません。

**LuLu：** ウィンドウ中に RoamSwitch 由来の外向きイベントはゼロ。

**entitlements**（`codesign -d --entitlements`）：

```
RoamSwitchHelper     -> <dict></dict>
RoamSwitchMCPServer  -> <dict></dict>
```

空。`com.apple.security.network.client` すらありません。（RoamSwitch は
サンドボックス化されていないので、これ自体は何も**強制しません** — だから挙動で見ます。）

### キャプチャ全体の HTTPS 宛先（TLS SNI）

```
bag.itunes.apple.com       gspe35-ssl.ls.apple.com    proxy-safebrowsing.googleapis.com
configuration.apple.com    init.push.apple.com        setup.icloud.com
dns.quad9.net              mask.icloud.com            swdist.apple.com
gateway.icloud.com         mesu.apple.com             swscan.apple.com
gsa.apple.com              ocsp2.apple.com            tether.edge.apple
p117-contacts.icloud.com   courier.push.apple.com     swallow.apple.com
fbs.smoot.apple.com
lafine.net
```

OS のサービス（iCloud、プッシュ通知、ソフトウェアアップデート、OCSP、Safari の
Safe Browsing）を除くと、宛先は `lafine.net` の1つ — Sparkle が `appcast.xml`
を取りに行ったもの（経路#2）。`dns.quad9.net` は DNS Threat Guard がシステムの
リゾルバを切り替えた結果で、暗号化 DNS の問い合わせは `mDNSResponder` であって
RoamSwitch ではありません。`swallow.apple.com` / `fbs.smoot.apple.com` は AWS の
IP に乗っていますが Apple のサービスです。`lafine.net` 以外の通信は、どれも
RoamSwitch のプロセスに帰属していません。

## この監査で確認できないこと

- 「通信を一切しない」ではありません。上の4経路は実在します。Zero Telemetry は
  「利用状況・診断結果を収集して送信するテレメトリをしない」という意味です。
- 「絶対に無い」でもありません。結論は観測したウィンドウの範囲に限定されます。
- ペイロードは検査していません（宛先と TLS SNI のみ）。解析 SDK・クラッシュ
  レポーター SDK は同梱していません。MCP サーバーと検知ロジックは OSS 公開のため
  「LLM に何を渡しているか」はコードで確認できます：
  <https://github.com/lafine1211/roamswitch-mcp>
- Sparkle の appcast チェックは24時間タイマー。この監査では起動時に強制発火させて
  ウィンドウ内で観測しています。
