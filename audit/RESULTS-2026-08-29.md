# Zero Telemetry audit — result, 2026-08-29

**English** | [日本語](RESULTS-2026-08-29.ja.md)

- **Verdict: PASS**
- Tool: [`rs-zerotel-audit.sh`](rs-zerotel-audit.sh) (this folder)
- Environment: macOS 26 / Apple Silicon
- RoamSwitch build: 1.4.7
- Window: a single ~2-hour session

## How it was run

The run was done on the maintainer's day-to-day machine. Claude Code, an IDE,
and the usual iCloud services were active — so this is **not** a "silent
machine" claim. The method is per-process attribution: `tcpdump` (all
interfaces), a `nettop` counter and a polled `lsof` snapshot mapping sockets to
processes, an Apple `pktap` capture filtered to the RoamSwitch binaries, and
LuLu's unified-log events. RoamSwitch's security level was pinned to **Maximum
Lockdown** with the manual override for the whole window (its `pf` rules must
still let only the four documented paths out). During the session the appcast
check was forced (`SULastCheckTime` deleted + relaunch), every MCP tool was
driven over stdio, `freshclam` was run, every in-app feature was exercised once,
and one network transition was triggered.

Allowlist (anything else from a RoamSwitch process = fail) — from
[`docs/WHITEPAPER.md`](../docs/WHITEPAPER.md) §7:

| # | destination | process | when |
|---|---|---|---|
| 1 | `lafine.net /api/v1/license/*` | RoamSwitch | license activate / deactivate only |
| 2 | `lafine.net /updates/appcast.xml` | RoamSwitch | Sparkle (launch + every 24 h) |
| 3 | ClamAV mirrors | `freshclam` (not the app) | only if ClamAV is installed |
| 4 | `HEAD` to a target URL | RoamSwitch | only when the in-app Link Safety sheet is used |

## Result

**Outbound flows attributed to `RoamSwitch` / `RoamSwitchHelper` /
`RoamSwitchMCPServer`: none** (non-loopback). `pktap` filtered to those three
process names captured zero packets.

**MCP server:** the only sockets it opened were to `127.0.0.1` (localhost) — the
`get_exposed_ports` tool checking HTTP headers on locally-listening ports. It is
read-only and speaks over stdio; nothing left the machine.

**LuLu:** no RoamSwitch-related outbound events for the duration.

**entitlements** (`codesign -d --entitlements`):

```
RoamSwitchHelper     -> <dict></dict>
RoamSwitchMCPServer  -> <dict></dict>
```

Empty — not even `com.apple.security.network.client`. (This does not by itself
*enforce* anything, because RoamSwitch is not sandboxed; hence the behavioural
check.)

### Every HTTPS destination in the whole capture (TLS SNI)

```
bag.itunes.apple.com       gspe35-ssl.ls.apple.com    proxy-safebrowsing.googleapis.com
configuration.apple.com    init.push.apple.com        setup.icloud.com
dns.quad9.net              mask.icloud.com            swdist.apple.com
gateway.icloud.com         mesu.apple.com             swscan.apple.com
gsa.apple.com              ocsp2.apple.com            tether.edge.apple
p117-contacts.icloud.com   courier.push.apple.com     swallow.apple.com
fbs.smoot.apple.com
lafine.net
```

Everything here is an OS service (iCloud, push, software update, OCSP, Safari
Safe Browsing) except `lafine.net` — Sparkle fetching `appcast.xml` (egress path
#2). `dns.quad9.net` is there because the DNS Threat Guard switched the system
resolver; the encrypted lookups are `mDNSResponder`'s, not RoamSwitch's.
`swallow.apple.com` / `fbs.smoot.apple.com` sit on AWS IPs but are Apple
services. None of the non-`lafine.net` traffic is attributed to a RoamSwitch
process.

## What this audit cannot show

- Not "no traffic at all" — the four paths above are real. Zero Telemetry means
  no collection or transmission of usage / diagnostic data.
- Not "never" — the conclusion is scoped to the observed window.
- No payload inspection (destination + TLS SNI only). No analytics or
  crash-reporter SDK is bundled; the MCP server and detection logic are open
  source, so "what is sent to the LLM" is checkable in code:
  <https://github.com/lafine1211/roamswitch-mcp>
- Sparkle's appcast check runs on a 24 h timer; this audit forces it on startup
  so the check is observed within the window.
