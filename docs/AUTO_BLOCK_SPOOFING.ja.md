# 自動遮断は悪用されないか 検証できていること、いないこと

2026年9月25日付。対象は Mac 1.10.3 と Linux 1.10.4 です。ソースと単体テストを読んだ結果で、
実機での攻撃の再現は、ラボでの測定を明記したものを除き、行っていません。

偽造パケットで正当な相手を遮断させられるなら、自動遮断は攻撃者の道具になります。
このページは、検討した経路と、それぞれを止めているもの、残っている弱点を挙げます。

## ポートスキャンの自動遮断(Mac と Linux)

SYNスキャンはハンドシェイクを完了しないため、送信元アドレスは送り手が自由に書けます。

| ケース | 結果 | テスト |
|---|---|---|
| 送信元がデフォルトゲートウェイ、DNSリゾルバー、自分自身の偽造SYN | 検知と記録は行い、遮断はしない | Mac `PortScanProtectedAddressesTests`、Linux `gateway_resolver_and_own_address_are_never_blocked` |
| ループバック、ブロードキャスト、マルチキャスト、未指定アドレス | 遮断しない | 同上 |
| 送信元が同一リンク上の別の端末(Linux) | 遮断しない。フレームの送信元MACが、近隣テーブルのMACと違うため | Linux `a_forged_on_link_source_is_not_blocked` |
| 送信元がリンク外のアドレス(Linux) | ゲートウェイのMACから来たフレームでなければ遮断しない | Linux `off_link_sources_must_arrive_via_a_gateway_mac` |
| Macで、ゲートウェイ、リゾルバー、自分以外の偽造 | 一定時間、遮断され得る。遮断は新規の受信TCP接続だけに絞ってあり、応答や確立済みの通信は続く | Mac `PFRulesetCoordinator` の `flags S/SA` ルール |
| 偽造SYNの洪水 | ログは毎秒200件に制限し、超えた分は数える。ラボで毎秒約7万の偽造SYNが約900行のログになった。飽和は6時間に1回まで通知する | Linux 1.9.87 |
| pfの状態テーブルを埋める洪水(Mac) | 1.9.47で修正。ラボでは偽造SYN 100本のうち24件が3秒後も状態を残していた。送信元がばらばらの洪水は遮断の対象にならない | Mac 1.9.47 |

既知の限界です。

- Macは、送信元MACを確認できません。`pflog0` のフレームにEthernetヘッダがないためです。
- Linuxでは、偽造者が先に、そのアドレスを名乗るARP要求を1つ送ると、近隣テーブルが偽造者のMACに書き換わります。
  2026年9月20日に、隔離したラボで測定しました。ゲートウェイのARP項目は、ARP固定でも守っています(Linuxは既定オン、Macは
  Pro限定で既定オフ)。
- 上の偽造ケースは、このページのために、実機で改めて再現してはいません。

## ARPスプーフィング検知とAir-Gap

ゲートウェイのMACの変化を検知すると、ロックダウン中、またはユーザーが警告で「今すぐ全遮断」を選んだときに、
ネットワークの全遮断(Air-Gap)に至ります。偽造したARP応答だけで検知が働くため、同じセグメントの攻撃者は警告を
出させることができます。設計上、DoSの余地は残っています。

- Mac: ロックダウン以外では、警告するだけです。Air-Gapは、ユーザーの選択かロックダウンのときだけです。
  読み取り専用の判定(ARPキャッシュを、連続3回、60秒にわたって読み、正規のMACが見えたとき)で、
  原因が解消したと確認できれば、ARP起因の隔離を自動で解除します。隔離の間は、ゲートウェイのARPの項目が
  近隣テーブルから消えることがあり(実機のMacで確認)、その場合は確認できず、手動で解除するまで残ります。
  セキュリティホワイトペーパーの§4も、2026年9月26日から、同じ内容です。この組み合わせを、実機のMacで、
  通しでは再現していません。
- Linux: ゲートウェイの近隣エントリがないとき、ARP再確認が直接ARP要求を送ります
  (`arp_recheck_active_probe`、既定オン、1.9.91以降)。隔離が解けなくなる状況を減らすためです。

## ラボの結果

上のLinuxのケース(偽のゲートウェイARP、偽装した送信元のSYNスキャン、ARPによる隔離の解除)は、2026年9月26日に、実機のカーネルと実際のLANで実行しました。[REAL_HOST_TESTS_2026-09-26.ja.md](REAL_HOST_TESTS_2026-09-26.ja.md) を参照してください。この試験で、1台の機器が2つのIPに答えるだけで、lockdownのマシンが完全に遮断されること、サービスを再起動するたびに、隔離の記録が失われることを見つけ、直しました。

## 未検証

- ゲートウェイ自身のMACを複製した不正アクセスポイントで、信頼済みネットワークと誤判定され、保護が緩むかどうか。
  測っていません。ルーターと同じMACを持つ機器を置くと、試験用のLANの実際のスイッチが混乱するためです。
  MACの比較では、複製とルーターを見分けられないので、ゲートウェイMACだけで信頼を判定するネットワークは、信頼されます。
- 上記のどれについても、第三者による再現。
